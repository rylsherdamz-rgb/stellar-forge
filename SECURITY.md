# Security Policy

## Supported Versions

| Version | Supported |
|---------|----------|
| 1.x     | ✅ |

## Reporting a Vulnerability

The Stellar Agentic Framework is a development harness for building Stellar dApps. It does not handle production secrets, user funds, or private keys directly.

If you discover a security issue:

1. **Do not** open a public GitHub issue
2. **Do not** post details in public forums
3. Email the maintainer directly or open a [GitHub Security Advisory](https://github.com/rylsherdamz-rgb/stellar-forge/security/advisories/new)

### What to Report

- Hardcoded secrets or API keys in templates or code
- Code generation patterns that introduce vulnerabilities (XSS, injection, improper auth)
- Unsafe defaults in scaffolded projects
- Dependency vulnerabilities in the CLI or templates

### Response Timeline

- Acknowledgment: within 48 hours
- Assessment: within 5 business days
- Fix: timeline depends on severity

## Security Best Practices for Scaffolded Projects

The framework templates follow these security principles:

- **No hardcoded secrets**: all secrets via `.env` / `.env.local`
- **x402 middleware**: validates payment headers server-side, never trusts client
- **Contract auth**: all privileged functions use `__check_auth`
- **CORS**: configurable origin whitelist in backend templates
- **Wallet connection**: handled client-side via Stellar Wallets Kit, never expose secret keys
- **MCP config**: no secrets in `.mcp.json`, use env vars with user-provided values

## Scope

This policy covers:

- `SKILL.md` and `CLAUDE.md` (harness logic)
- Agent definitions in `agents/`
- Templates in `templates/`
- CLI in `packages/create-stellar-agentic/`
- Skill files in `skills/`

Excluded:

- The Stellar network itself
- Third-party dependencies installed by scaffolded projects
- User's own application code generated by the framework
